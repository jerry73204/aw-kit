# Phase 3: Resolver & Build Graph

> Compute the dependency graph: which components need which images, which need rebuilds, and in what order.

---

## Design

The resolver is the core decision engine. It takes the parsed manifest + resolved platform and produces a `BuildPlan` — an ordered list of build steps that downstream codegen and builder phases execute.

### Build step types

```rust
enum BuildStep {
    Pull {
        component: String,
        image: String,        // full image URI with tag
    },
    BuildOverlay {
        component: String,
        base_image: String,
        dockerfile: PathBuf,  // will be generated by codegen
        context: PathBuf,
        tag: String,
        layer_type: LayerType,
    },
}

enum LayerType {
    PlatformRebuild,   // Orin L4T rebuild
    Patch,             // [patch.<component>] overlay
    Extension,         // [[package]] extends
}
```

### Layer stacking order

For a given component, layers stack in this fixed order:

```
1. upstream image  (always: pull)
2. platform rebuild (if Orin + CUDA component)
3. patch overlay    (if [patch.<component>] exists)
4. extension        (if [[package]] extends this component)
```

Each layer's base image is the output of the previous layer.

### Image tagging scheme

```
<registry>/<prefix>/<component>:<aw-version>[-<platform>][-p<patch-hash>][-x<ext-hash>][-<arch>]
```

- `patch-hash`: short SHA of combined patch source digests
- `ext-hash`: short SHA of combined extension package source digests

### Source fetching

The resolver also determines what source needs to be available:

- `PatchSource::Git { git, branch }` → clone into `.aw-kit/src/<package>/`
- `PatchSource::Path { path }` → validate path exists, use as-is
- `Package { path }` → validate path exists

### Incremental build detection

Compare current source digests against `Autoware.lock` entries. Skip steps whose inputs haven't changed. This requires:

- Hashing source directories (tree hash, similar to git's)
- Comparing against `patch-digest` and `source-digest` in the lock file

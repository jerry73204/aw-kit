# Phase 4: Code Generation (Dockerfile + Compose)

> Generate Dockerfiles for overlay builds and `docker-compose.yml` for orchestration.

---

## Design

Codegen is the "compiler backend" of aw-kit. It takes the `BuildPlan` from the resolver and emits concrete files into `.aw-kit/build/` and `.aw-kit/compose/`. These files are generated artifacts — never edited by users, always gitignored.

### Output directory structure

```
.aw-kit/
├── build/
│   ├── localization.Dockerfile              # patch overlay
│   ├── perception.orin.Dockerfile           # platform rebuild
│   ├── planning.extended.Dockerfile         # custom package extension
│   └── ...
├── compose/
│   └── docker-compose.yml                   # generated compose
├── src/                                     # fetched patch sources (from Phase 3)
│   ├── ndt_scan_matcher/
│   └── lidar_centerpoint/
└── .gitignore                               # ignore everything in .aw-kit/
```

### Dockerfile generation

Three Dockerfile templates, one per `LayerType`:

**PlatformRebuild** — rebuild CUDA-dependent packages from L4T base:
- Multi-stage: builder (L4T CUDA devel) + runtime (L4T JetPack)
- Copies component source at pinned version
- Builds with `CMAKE_CUDA_ARCHITECTURES` from `ResolvedPlatform`
- Needs a list of CUDA-dependent packages per component (hardcoded initially, later queryable)

**Patch** — overlay a patched package on top of the component image:
- Single stage: FROM the component (or platform-rebuilt) image
- COPY patch source into overlay workspace
- `colcon build --packages-select <package>`
- Append overlay source to setup chain

**Extension** — add a custom user package:
- Same pattern as Patch but for user-authored packages
- FROM the component (or patched) image
- COPY package source, colcon build, append setup

All generated Dockerfiles include the header comment: `# [GENERATED by aw-kit — do not edit]`

### Compose generation

The compose file maps each enabled component to a service:

```yaml
services:
  localization:
    image: <resolved image for localization>
    network_mode: host
    # if nvidia runtime:
    runtime: nvidia
    # if Orin device mounts:
    devices:
      - /dev/nvhost-ctrl
      - ...
```

Additional compose concerns:
- `network_mode: host` for DDS/ROS2 discovery
- Volume mounts for maps, vehicle config (passed through, not managed)
- Environment variables: `ROS_DOMAIN_ID`, etc.
- Correct `depends_on` ordering if needed

### DevContainer generation (for `[[package]]`)

When custom packages are declared, generate `.devcontainer/devcontainer.json` per the design doc section 4.4. This enables VS Code remote container development against the component's image.
